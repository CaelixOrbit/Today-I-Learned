# Git 工作区域与文件状态

## 工作区域

Git 项目包含三个主要的工作区域，分别对应文件的不同管理阶段：

- **工作区（Working Directory）**

  工作区是从 Git 数据库中检出的某个版本的项目文件副本，是用户直接查看和修改文件的地方。

  工作区中的文件可能处于未跟踪或已修改状态。

  使用 `git add` 命令可以将工作区中的文件添加到暂存区。

- **暂存区（Staging Area / Index）**

  暂存区也称为索引，是一个包含文件索引的内部文件（通常位于 `.git/index`），作为临时存储区域，用于保存即将写入下次提交的快照。

  使用 `git commit` 命令可以将暂存区中的内容提交到本地仓库。

- **本地仓库（Local Repository）**

  本地仓库是位于项目根目录下 `.git` 目录中的数据库，用于存储项目元数据和所有提交历史记录。每次提交更改时，Git 会将暂存区中的内容作为新的快照提交到本地仓库中。

## 文件状态

在工作区中的文件可能处于以下几种状态之一：

- **未跟踪（Untracked）**

  文件存在于工作区中，但尚未被 Git 跟踪，即未纳入版本控制。

被 Git 跟踪的文件主要处于以下三种状态之一，分别对应上述三个工作区域：

- **已修改（Modified）**

  文件在工作区中被修改，但尚未添加到暂存区。

- **已暂存（Staged）**

  文件的当前版本已被存储在暂存区，将包含在下次提交的快照中。

- **已提交（Committed）**

  文件已安全存储于本地仓库的数据库中，成为项目历史记录的一部分。

## `git status` 命令

`git status` 命令用于查看 Git 仓库的当前状态。

通过执行 `git status`，可以了解自上次提交以来，工作目录中文件是否发生了新的修改。

该命令会显示以下信息：

- 当前所在分支的名称。

- 当前分支与远程分支的关系（例如，是否为最新）。

- 未暂存的修改：已修改但尚未使用 `git add` 添加到暂存区的文件。

- 未跟踪的文件：尚未纳入 Git 版本控制的新文件。

使用 `-s` 或 `--short` 选项，可以获得简化的状态输出，每个文件的状态会以两个字符的代码表示，格式如下：

```bash
XY 文件名
```

其中：

- 第一个字符（X）：表示文件在暂存区的状态，可能的值包括：

  - `A`：新添加到暂存区的文件（之前未被跟踪）；

  - `M`：文件已被修改并添加到暂存区；

  - `D`：文件已删除，且删除操作已记录到暂存区；

  - `R`：文件已重命名，且重命名操作已记录到暂存区。

- 第二个字符（Y）：表示文件在工作区的状态，可能的值包括：

  - `M`：文件在工作区中被修改，但尚未暂存；

  - `D`：文件在工作区中被删除，但尚未暂存。

- 其他状态：`??` 表示该文件未被 Git 跟踪。

常见状态标识如下：

| 标识（XY） | 状态说明                                               |
| :--------: | :----------------------------------------------------- |
|    `??`    | 文件未被 Git 跟踪                                      |
|    `A `    | 新添加到暂存区的文件（之前未被跟踪）                   |
|    ` M`    | 文件在工作区中被修改，但尚未暂存                       |
|    `M `    | 文件已被修改并添加到暂存区                             |
|    `MM`    | 文件已被修改并添加到暂存区后，在工作区又发生了新的修改 |
|    ` D`    | 文件在工作区中被删除，但尚未暂存                       |
|    `D `    | 文件已删除，且删除操作已记录到暂存区                   |
|    `R `    | 文件已重命名，且重命名操作已记录到暂存区               |
