# Git 远程仓库

远程仓库是托管在网络服务器上的 Git 仓库，允许多个开发者通过 `fetch`、`pull`、`push` 等网络操作同步各自的工作。

> [!NOTE]
>
> 远程仓库的 "远程" 并不一定表示仓库位于网络或互联网上，而是表示它位于当前本地仓库之外。远程仓库也可以是同一台计算机上的另一个目录。无论远程仓库的具体位置如何，与其同步数据时使用的命令是基本一致的。

## 远程仓库配置

一个本地仓库可以同时关联多个远程仓库，每个远程仓库以一个简写（shortname）作为本地别名。

- **查看远程简写**：

  ```bash
  # 查看已配置的远程简写
  git remote
  
  # 查看远程简写及其对应的 URL
  git remote -v
  ```

- **添加远程简写**：

  ```bash
  git remote add <shortname> <url>
  ```

- **修改远程简写**：

  ```bash
  git remote rename <old-name> <new-name>
  ```

- **移除远程简写**：

  ```bash
  git remote remove <shortname>
  ```

上述命令仅用于为涉及网络请求的命令配置远程 URL 及其对应简写。配置本身不涉及网络请求，也不会对远程仓库中的实际数据产生任何影响，配置内容存放在本地 `.git/config` 文件中。

## 远程分支与跟踪机制

在 Git 的网络协作中，存在三种名称相似，但本质完全不同的分支概念：

- **远程分支（Remote Branch）**

  远程分支是存在于远程仓库中的引用，其状态完全由远程服务器在内部进行自动维护。

- **远程跟踪分支（Remote-tracking Branch）**

  远程跟踪分支是存在于本地仓库中的对远程分支状态的只读引用。反映的是对应远程分支在上一次执行网络抓取时的状态。命名格式通常为 `<shortname>/<remote-branch-name>`。

  这类分支的指针无法被手动移动。只有在执行涉及网络请求的操作（如 `git fetch` 或 `git pull`）时，Git 才会自动拉取数据并更新该指针，使其与远程仓库的状态保持同步。

  此外，尽管其本身仅作为只读指针存在，但所指向的快照内容可以被合并到其他的本地分支中。

  > **注**：无法手动移动是指：检出此类分支会触发 "分离头指针" 状态，此时 HEAD 直接指向提交而非分支引用。在这种状态下产生的新提交不会带动远程跟踪分支指针前移，仅由 HEAD 独自追踪。若未及时为这些新提交创建分支引用，一旦 HEAD 移开，这些提交将因失去引用保护而沦为 "悬空对象"，并最终被垃圾回收机制清除。

- **跟踪分支（Tracking Branch）**

  跟踪分支（也称为本地跟踪分支）是存在于本地仓库中的实体分支，其特殊之处在于它显式绑定了一个远程跟踪分支作为自己的 "上游分支（Upstream Branch）"。

  在跟踪分支上执行 `git pull` 或 `git push` 时，Git 会自动解析对应的远程仓库与远程分支，确定数据拉取与推送的目标。执行本地操作时与普通分支无异。

> [!NOTE]
>
> 远程跟踪分支和对应的远程分支的名字相同。
>
> 跟踪分支和其绑定的远程跟踪分支的名字可以不同，但最好不要这样做。

## 跟踪关系配置

- **创建跟踪分支**：

  ```bash
  # 基于远程跟踪分支，创建带有上游绑定的跟踪分支
  git checkout -b <branch-name> <shortname>/<remote-branch-name>
  
  # 快捷写法：使用 --track 选项（本地自动同名）
  git checkout --track <shortname>/<remote-branch-name>
  
  # 极简写法：当本地无该分支，且远程存在唯一的同名分支时，自动创建并绑定
  git checkout <branch-name>
  git switch <branch-name>
  ```

- **修改跟踪关系**：

  ```bash
  # 为本地分支绑定上游分支，缺省默认为当前分支
  git branch -u <shortname>/<remote-branch-name> [<branch-name>]
  ```

## 查看远程仓库

使用 `git remote show` 命令，会发起网络请求，获取远程仓库的当前实际状态，并与本地的追踪记录进行比对。

```bash
git remote show <shortname>
```

此命令输出的主要信息包括：

- **URL 信息**：该远程仓库的 URL、Fetch URL 与 Push URL。

- **默认分支**：远程仓库当前的默认主分支。

- **远程分支状态**：

  - `tracked`：本地已正常追踪。

  - `new`（新分支）：远程分支已创建，但本地尚未执行拉取（`fetch`）的新分支。

  - `stale`（失效分支）：远程分支已被删除，但本地仍残留对应的远程跟踪分支（提示可使用 `git remote prune <shortname>` 清理）。

- **拉取映射**：列出跟踪分支在执行 `git pull` 时，默认抓取并合并的对应远程分支。

- **推送映射**：列出执行 `git push` 时的默认推送流向，并标注同步状态：

  - `up to date`：**已完全同步**。本地与远程历史完全一致，无需任何操作。

  - `fast-forwardable`：**本地领先**。本地包含了远程的所有历史，并有新增的线性提交，可安全执行快进推送。

  - `local out of date`：**本地滞后**。本地缺少远程的最新提交，或双方历史已产生分叉，此时推送将被服务器直接拒绝，必须先执行拉取与合并。

## 获取、拉取与合并

- **获取数据（Fetch）**：

  访问远程仓库，下载所有本地缺失的数据，并更新本地的远程跟踪分支指针。

  ```bash
  # 访问当前分支所关联的远程仓库
  git fetch
  
  # 访问指定远程仓库
  git fetch <shortname>
  ```

## 推送与共享

- **推送分支（Push）**：

  本地分支不会自动与远程同步，必须显式推送到有写入权限的远程仓库。

  ```bash
  # 将本地分支推送到远程仓库
  git push <shortname> <branch-name>
  
  # 将本地分支推送到指定的远程分支名（若远程不存在则创建）
  git push <shortname> <branch-name>:<remote-branch-name>
  
  # 使用 -u 选项推送并建立本地分支与远程分支的跟踪关系
  git push -u <shortname> <branch-name>
  
  # 若当前分支已建立跟踪关系，直接推送至对应的远程分支
  git push
  ```

- **共享标签**：

  默认情况下，`git push` 不会传送标签，必须显式推送：

  ```bash
  # 推送特定标签
  git push <shortname> <tag-name>
  
  # 显式推送并重命名远程标签
  git push <shortname> <tag-name>:<remote-tag-name>
  
  # 一次性推送所有尚未推送的本地标签
  git push <shortname> --tags
  ```

## 删除远程引用

当分支开发完成并合并后，可以清理远程仓库上的冗余记录：

```bash
# 删除远程分支
git push <shortname> --delete <remote-branch-name>

# 快捷写法：推送一个空分支到远程，等同于删除该远程分支
git push <shortname> :<remote-branch-name>

# 删除远程标签
git push <shortname> --delete <tag-name>

# 快捷写法：推送一个空标签到远程，等同于删除该远程标签
git push <shortname> :<tag-name>
```
