# Git 基本操作

![](./Git%20工作流程.png)

## 暂存更改

使用 `git add` 命令将文件的修改添加到暂存区。

```bash
# 添加一个或多个文件到暂存区
git add <file1> [<file2> ...]

# 添加指定目录到暂存区（包括子目录）
git add <dir>

# 添加当前目录下的所有文件到暂存区
git add .
```

## 提交变更

使用 `git commit` 命令将暂存区的内容作为新的快照提交到本地仓库。

```bash
# 提交暂存区内容到本地仓库并附加说明信息
git commit -m "<message>"

# 提交指定的已暂存文件到本地仓库
git commit <file1> [<file2> ...] -m "<message>"

# 使用 -a 选项可自动暂存并提交所有已跟踪且已修改的文件，无需先执行 git add
git commit -am "<message>"
```

> [!NOTE]
> 
> 不加 `-m` 选项，Git 会默认打开 Vim 等终端编辑器，允许编写更详细的多行提交说明。

## 忽略文件（.gitignore）

并非所有文件都需要纳入 Git 的版本控制（如编译生成的临时文件、日志文件、包含密码的配置文件等）。在项目根目录下创建一个名为 `.gitignore` 的文件，Git 会根据其中定义的模式匹配规则来忽略指定的文件或目录。

- **通配符**：可以使用标准 glob 模式（即标准 Shell 通配符）匹配，模式默认会递归地应用在 `.gitignore` 所在目录及其子目录中。

- **路径分隔符**：

  - **以斜杠 `/` 开头**：表示只匹配 `.gitignore` 文件同级目录下的对应项，不再向下递归搜索。

  - **以斜杠 `/` 结尾**：表示递归匹配项目中任何位置的该名称文件夹，并忽略其内部所有内容。

- **取反操作**：以 `!` 开头表示重新包含被之前规则忽略的项。（注：若父目录已被忽略，则对其子项取反无效。）

- **多级匹配**：使用 `**` 表示匹配任意中间目录。

> [!NOTE]
> 
> `.gitignore` 规则只对尚未被 Git 跟踪的文件有效。如果文件已处于已跟踪状态，必须先执行 `git rm --cached <file>` 将其从暂存区移除，忽略规则才会生效。

## 查看修改差异

`git status` 只能显示哪些文件发生了修改，而 `git diff` 可以精确显示文件更改详情。

不加选项时，显示未暂存的修改；附加选项 `--staged` 或 `--cached` 时，显示已暂存的修改：

```bash
# 查看工作区与暂存区之间的差异（即未暂存的修改）
git diff

# 查看暂存区与最后一次提交（HEAD）之间的差异（即已暂存的修改）
git diff --staged
git diff --cached
```

## 移除与重命名文件

在 Git 中移除或重命名文件，建议使用 Git 提供的专有命令（PS：其实不用也行），以确保这些操作被正确记录到暂存区中。

```bash
# 从工作区和暂存区中同时删除文件（物理删除并取消跟踪）
git rm <file-name>
# PS：其实手动删除再执行 git add 也行 :P

# 仅从暂存区中移除文件，但保留在工作区（取消跟踪，但不删物理文件，常用于配错的忽略文件）
git rm --cached <file-name>

# 重命名文件，相当于依次执行了 mv、git rm、git add 三步操作
git mv <old-file-name> <new-file-name>
# Git 并不跟踪文件的 "重命名"，而是用一定算法自动推断是重命名，推断方法较为复杂不解释
```
