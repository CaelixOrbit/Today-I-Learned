# Git 分支管理

几乎所有版本控制系统都以某种形式支持分支，一个分支代表一条独立的开发线。

使用分支意味着可以从开发主线上分离，在不影响主线的同时继续工作。

在 Git 中，分支实际上是指向快照的指针。

## 基本分支操作

- **创建分支**：

  ```bash
  # 在指定节点处创建新分支，缺省默认为 HEAD 处
  git branch <branch-name> [<commit-hash>]
  
  # 强制创建或移动非当前分支指针，即使分支已存在也将强行将其移至指定节点
  git branch -f <branch-name> [<commit-hash>]
  ```

- **切换分支**：

  ```bash
  git checkout <branch-name>
  
  # Git 2.23 版本引入的专用切换命令
  git switch <branch-name>
  ```

  也可以使用以下命令创建新分支并立即切换到该分支：

  ```bash
  git checkout -b <branch-name>
  
  # Git 2.23 版本引入的新建并切换命令
  git switch -c <branch-name>
  ```

  切换分支时，Git 会使用该分支中最后提交的快照替换工作目录的内容，因此多个分支不需要多个目录。

- **查看分支**：

  ```bash
  # 仅查看本地分支（当前分支以 * 标注）
  git branch
  
  # 查看远程跟踪分支
  git branch -r
  
  # 查看所有分支（包含本地与远程）
  git branch -a
  
  # 查看分支详细信息：显示最后一次提交信息，并展示与上游分支的追踪关系
  git branch -vv
  ```

- **删除分支**：

  ```bash
  # 删除本地分支
  git branch -d <branch-name>
  
  # 强制删除本地分支（未合并时使用）
  git branch -D <branch-name>
  ```

- **分支改名**：

  ```bash
  # 重命名本地分支
  git branch -m <old-branch-name> <new-branch-name>
  
  # 强制重命名，即使新分支名已经存在
  git branch -M <old-branch-name> <new-branch-name>
  ```

## 分支合并

当分支开发完成独立内容后，通常需要将其合并回主分支。可以使用以下命令将其他分支合并到当前分支：

```bash
git merge <branch-name>
```

不加选项时，Git 会根据当前分支与目标分支的历史拓扑结构自动决定合并机制，主要包含以下两种情况：

- **快进合并（Fast-forward）**：当目标分支是当前分支的直接后继时，Git 会直接将当前分支的指针移动到目标分支指向的快照，不会创建新的快照。

也可以通过添加选项来指定合并行为，以满足特定的历史记录管理需求：

```bash
# 强制生成合并提交（禁用快进合并，常用于保留特性分支的完整独立历史）
git merge --no-ff <branch-name>

# 仅允许快进合并（若存在分叉历史导致无法快进，则直接拒绝合并并报错）
git merge --ff-only <branch-name>
```

## 合并冲突

分支合并时，当两个分支对同一个文件的同一部分进行了不同的修改，Git 无法自动决定应该采用哪种更改时，就会发生合并冲突。此时合并过程会暂停，需要手动解决冲突后才能完成合并。

Git 会用 `<<<<<<<`，`=======`，`>>>>>>>` 标记出不同分支的修改内容，如下所示：

```
<<<<<<< HEAD
当前分支的修改内容
=======
要合并分支的修改内容
>>>>>>> branch-name
```

解决冲突步骤：

1. 使用 `git status` 查看冲突文件。

2. 打开冲突文件，手动编辑冲突部分，保留需要的修改，删除标记。

3. 使用 `git add` 将解决冲突后的文件标记为已解决。

4. 使用 `git commit` 提交合并结果。

如需放弃合并过程，可使用 `git merge --abort` 命令回退到合并前状态。

> **注**：解决合并冲突的过程，本质上是用户手动干预三方合并的结果。Git 将合并过程中无法自动解决的冲突标记出来，由用户决定最终的文件内容。此时，用户可以对文件进行任意修改，甚至包括与冲突部分无关的更改，亦或是删除文件，Git 不会限制这些修改，但最终提交的内容将作为合并结果。用户解决冲突后，通过 `git add` 和 `git commit` 完成合并提交。
